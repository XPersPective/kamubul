# ADR-012 — Asistan yanıt bildiriminin güvenlik sınırı

Status: PROPOSED

## Problem

SA-024 kullanıcıya uygulamadan çıkmadan AI yanıtını bildirme olanağı vermeli.16Ekim kaynak okuması önemli bir tasarım varsayımını çürüttü: AssistantClient yalnız yerel rastgele assistantId gönderiyor, Bearer kimlik doğrulaması yok. Worker authenticate/registry yalnız push installations içindir; kayıt fcmToken zorunlu tutar. Bu kimlik akışını geri bildirime doğrudan bağlamak bildirim kapalı kullanıcıyı dışlar.

## Evidence

- `lib/data/assistant_client.dart`: _installationId/ask; anonim32hex kimlik auth kanıtı değildir.
- `workers/src/worker.js`: authenticate/registry ve /api/v2/assistant; push kaydı FCM token gerektirir.
- `lib/ui/assistant_chat.dart`: gerçek API yanıtı ile yerel hata/welcome mesajı aynı ChatMessage.assistant türünde; raporlanabilirlik ayrı metadata ile belirlenmeli.
- Android backup XML yalnız eski FlutterSecureStorage adını dışlıyor; yeni draft/receipt verisi sıradan tercih deposuna konursa backup kapsamı ayrıca doğrulanmalı.
- [Google AI policy](https://support.google.com/googleplay/android-developer/answer/13985936?hl=en),16Ekim tekrar okundu: uygulama içinde bildirim ve raporlardan filtre/moderasyon süreci gerekir.
- [Workers Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/),16Ekim tekrar okundu: yerleşik HMAC sign/verify ve SHA256 kullanılabilir; yeni kripto paketi gerekmiyor.

## Options

1. Push installation auth'ını kullan. Mevcut FCM zorunluluğu kaldırılmadan uygun değil; rapor göndermek için kullanıcıdan push izni/FCM kimliği isteme. Yeni genel kurulum kaydı tasarımı bu küçük işin kapsamını genişletir.
2. Anonim içerik raporu + sadece IP/global sınır. En küçük endpoint; gerçek server yanıtı ile uydurma içeriği ayıramaz. Anonim assistantId doğrulanmış kullanıcı gibi gösterilemez.
3. Server yanıtına bağlı imzalı raporlama kanıtı. Yanıtın özeti, rastgele response ID, sürüm/audience ve süre sınırı HMAC ile bağlanır. Kullanıcı seçili yanıtı açık önizlemeyle gönderir; model/rapor metni talimat sayılmaz. Push/profil/sohbet geçmişi gerektirmez. Ayrı server signing binding, idempotency, silme makbuzu ve kötüye kullanım sınırları gerekir.

## Candidate

3 tercih edilen yön. Yeni anahtar provider/FCM anahtarından türetilmez; client/APK/Git/log'a konmaz. Key yokken yayımlanmış AI yanıtının raporlanamaz kalması release kapısıdır. Bu ADR henüz ACCEPTED veya task READY değildir.

## Contract to finish before READY

- Ticket alanları/byte sınırı/süre ve canonical reply hash; native std WebCrypto doğrulaması. Aynı AIyanıtı/retry için tek kayıt ve değişen payload'a açık conflict.
- İstek yalnız seçili yanıt+neden+isteğe bağlı kısa not+rapor metadata'sı; bütün profil/geçmiş/FCM yok. UI preview/onay, ack öncesi başarı yok, offline draft ve açık vazgeçme/silme.
- Receipt/deletion yetkisi ve yerel draft'ın gerçek backup kapsamı. Önce napp_core SettingsStore gerçek backend'ini oku; sadece manifestteki eski güvenli-depo adına bakarak korunuyor deme.
- D1 retention ve kota işlemleri mevcut rate_limits/batch/maintenance kalıbıyla. Delete sonrası quota reset/doubletap yarışları gerçek SQLite/D1 davranışıyla test edilmeli.
- Operatör mevcut Cloudflare/D1 erişiminden bilinen test raporunu okuyup inceleme sonucu kaydeder; ayrı public admin endpoint/rolü veya otomatik mesaj gönderimi gerekmez. Raporların filtre/prompt düzeltmesine veya gerekçeli no-action'a bağlandığı süreç yazılır.
- Yayın öncesi canlı Worker model/config drift readback, signing binding, migration ve gerçek test-report ack/operator readback; privacy/Data Safety aynı veri akışı. Ürün kabulü ADR-010 ve mevcut maliyet/mahremiyet sınırları korunur.

## Impact

SA-024 HIGH tasarım işi sürer. SA-016 Pro doğrulaması ayrı kalır; anonim assistantId'ye yetki atfedilmez. SA-015 kararsız Android QA nedeniyle bloklu olsa da bu server/UI tasarımı ilerletilebilir. Mevcut üretim API/secret/ayar değiştirilmedi.
