# PB-013 — Anonymous identity, subscriptions and FCM push

## Status
IMPLEMENTED 2026-09-29 with a design change; NOT tested against real FCM/APNs. iOS push needs the Xcode push capability, entitlements and an APNs key (owner, Apple host).
## Objective
Firebase Anonymous Auth + App Check; devices register FCM token and saved-search filters; backend matches new listings deterministically and sends instant/digest pushes with quiet hours, daily cap and cross-source dedupe.
## Dependencies

- Notification taps deep-link to the listing; opt-out and "delete my notification data" work.
- Real-device end-to-end on Android; iOS verified when a host exists.

## Resume
2026-09-29: DESIGN CHANGE: instead of Firebase Anonymous Auth + App Check, the device generates a random 128-bit id and 256-bit secret; the server stores only SHA-256(secret) and requires it as a bearer token (constant-time compare), with per-IP write limits, a 32 KB body cap, whitelisted filter keys and stale-record cleanup after 120 days. This keeps the API portable (no Google auth dependency) and account-free. App Check remains an optional hardening step (PB-014). Server matching reuses the app's `decideAlerts` (instant/digest/quiet hours/daily cap/queue), a failed send requeues, invalid tokens delete the device, and unsent notifications survive a crash. The app registers only after an explicit user action (notification permission + switch) and deleting = switch off (`DELETE /v1/devices/{id}`). Firebase config comes from `--dart-define`, no google-services.json in the repo. Verified: 37 backend tests + 11 registration tests. Not verified: real FCM delivery, Android/iOS builds with the new plugins, tap routing from FCM.
