# PB-007 — Structured extraction pipeline

## Status
PLANNED
## Objective
Extract per-listing fields (kontenjan, yaş sınırı, eğitim, KPSS, şehir, unvan, deadline, quota type) into a versioned internal schema with mechanical error-proof gates, deterministic parsers first and AI only as a validated candidate generator.
## Dependencies
PB-002, PB-003
## Affected Areas
`lib/`, `test/`, `tool/`, `.project-brain/`
## Acceptance Criteria
- Internal listing schema v1 (with custom Turkish fields `maxAge`, `kpssRequirement`, quota types) is defined, versioned and validated in code.
- Deterministic per-source parsers produce schema candidates. An AI extractor may generate candidate JSON only where TD-001 provides an approved, non-embedded-key path; its fields enter the app only after: strict JSON-schema validation, verbatim source quote located in the fetched text, per-field confidence threshold.
- Fields failing any gate stay "belirtilmemiş" and the raw sentence is displayed; every shown structured field exposes its quote on demand.
- Labeled evaluation set of ≥50 real announcements per source with per-field precision/recall; extractors below the recorded bar degrade to raw-text display.
- PDF parsing runs only when born-digital and table-aware; otherwise the original document is presented.
## Verification
Risk: HIGH. Fixture tests, golden-JSON tests, drift detection, labeled-sample evaluation report per source.
## Architecture Impact
Expected: YES — data model, extraction boundary.
## Decision Boundary
Enabling a centrally paid AI extractor requires TD-001 resolution; redistribution terms per source require TD-002 checks.
