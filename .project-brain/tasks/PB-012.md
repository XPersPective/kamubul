# PB-012 — Server-side AI extraction and summary

## Status
BLOCKED on PB-010 and owner API key/service account.
## Objective
Once per new listing call the configured LLM for candidate fields and a bullet summary through a provider-agnostic adapter (Anthropic Messages, OpenAI-compatible Chat Completions with configurable base URL, Gemini); developer key server-side only; enforce the three C-005 gates.
## Dependencies
PB-010; owner chooses provider and budget (consumer chat subscriptions are not API access).
## Affected Areas
`backend/`, `packages/kamubul_core`, `test/fixtures/eval/`
## Acceptance Criteria
- Strict schema validation, verbatim quote located in the source text, confidence threshold per field; failing fields stay unspecified.
- Per-field precision/recall on the labeled corpus meets the recorded bar before a field is enabled; summaries labelled as AI.
- One adapter interface with Anthropic and OpenAI-compatible implementations tested against recorded responses (Gemini optional); provider/model/base URL/key are server config, switchable without an app release.
- Backend requests plain JSON and validates it itself; no gate depends on a provider's structured-output guarantee.
- Token cost per listing metered and a daily budget cap stops AI calls and falls back to deterministic parsing; no key in the app or repo.
## Verification
Risk: HIGH. Eval run against the labeled corpus; cost trace.
## Architecture Impact
Expected: YES.
## Decision Boundary
Enabling any AI field below the bar is forbidden.
