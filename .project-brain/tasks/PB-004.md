# PB-004 — Refresh and saved-search notifications

## Status
PLANNED
## Objective
Add manual/open and best-effort scheduled refresh plus notifications keyed to saved searches (etiketler), with digest modes and deadline reminders.
## Dependencies
PB-002, PB-003, PB-007
## Affected Areas
`lib/`, `android/`, `ios/`, `test/`
## Acceptance Criteria
- Each saved search has its own notification mode — instant / daily digest / off — plus an optional deadline reminder (X days before deadline) for matching or bookmarked listings.
- Cross-source reposts dedupe to one notification; digest runs in a daytime window with quiet hours; overflow lands in an in-app notification center; taps deep-link to the listing.
- Soft pre-permission explanation appears after the first saved search (never on first launch); permission denial leaves everything usable.
- Android/iOS background work is battery-conscious, retry-safe and never presented as guaranteed timing; manual refresh always works.
## Verification
Risk: HIGH. Logic tests (dedupe, digest windows, reminder scheduling) and Android/iOS release-device permission/network checks.
## Architecture Impact
Expected: YES — native scheduling, notification model.
## Decision Boundary
Guaranteed instant delivery needs a separate backend decision.
