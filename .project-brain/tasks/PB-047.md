## Objective
A reinstall cannot start a fresh 24-hour ad-free period because the trial endpoint was unavailable. Keep job listings and paid Pro available during verification.

## Steps
1. Report successful validation from the existing device hash endpoint. Keep the earliest stored or verified first-use date.
2. In ads_state.dart and main.dart, leave a genuinely fresh installation pending when validation fails. Retry once at a time when the app resumes and update ad eligibility using the restored date.
3. Keep the ad-free promotion to 24 hours, reuse the existing Pro status layout when validation is pending, and exercise fresh, returning, legacy and failed validation paths.

## Acceptance
- [ ] [machine] An offline fresh install writes no start date, existing first use dates persist and an old server date ends the provisional pending state.
- [ ] [visual] The existing paywall shows a short connection-dependent pending message in place of a countdown while verification is unavailable.
- [ ] [interaction] A foreground retry updates ad eligibility. Listing navigation and Pro purchase remain available while pending.
- [ ] [accessibility] The pending status appears as ordinary text in the existing accessible paywall.
